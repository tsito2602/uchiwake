# uchiwake

共有カードの月次明細と銀行引落の家賃を合計し、ふたりで折半して共有口座への入金額を出すMVP。React + Hono を Cloudflare Worker で配信します。

## ステージング

https://uchiwake-staging.tsito-apps.workers.dev/

専用 D1 `uchiwake-staging` を使います。画面とAPIは共有パスワードで保護しています。個人別認証とバックアップ方針が整うまでは実際の家計情報を登録しないでください。

## 使い方

1. 「取り込み」で**同じ共有カードの引落に含まれる**明細スクリーンショットを1〜3枚選びます。明細が複数画面に分かれる場合はまとめて選択します。画像は取り込み時の読み取りに使用し、保存しません。
2. AIが抽出した**複数の利用行**を確認します。日付、店名、費目、金額を修正でき、抜けた行は追加、重複した行は削除できます。返金はマイナス額で入力します。
3. **引落月**とカード請求の確定額を確認します。利用行の合計と引落額が一致し、元の明細との照合にチェックした場合だけ一括保存します。複数の請求がある場合は別々に取り込めます。保存後は費目を変更でき、金額や行の修正は明細単位で削除して再取り込みします。
4. ホームで銀行引落の**家賃**を手入力します。カード請求額と家賃などの合計を2人で折半した金額が入金目安です。奇数円は一方が1円多く負担します。
5. レポートは引落月に属するカード明細を費目別に集計します。従来のレシート記録は表示だけ残し、新しい計算には加えません。

対象は個人用カードの利用が混ざらない共有カードです。銀行明細の自動読み取り、カード会社との照合、PDF・CSV、画像原本の保存、個人別ログインは未対応です。

## AIの費用をかけないデモ

ステージングは **デモ・無料** が初期選択です。任意の画像を選ぶか「画像を用意せずサンプル明細で試す」を押すと、固定の3行が返ります。画像の内容は解析しません。OpenAIのAPIキーが設定されていてもデモ経路では呼び出しません。保存前の仕分け、確定額照合、入金額、費目別レポートまで試せます。

実際に画像をAIで読むときだけ **実際のAI・料金あり** を選びます。APIキーがない場合は選択できません。費目別レポートのコメントもデモは定型文で、AIを呼びません。デモはステージング限定です。

## 開発・デプロイ

```sh
npm ci
npm run check
npm run db:staging
npm run deploy:staging
```

`OPENAI_API_KEY` は `uchiwake-staging` Worker の Secret に設定します。コードや設定には記載しません。デプロイ前に D1 の `migrations/0002_card_statements.sql` を適用してください。モデルは `OPENAI_MODEL` (`gpt-6-luna`) です。
