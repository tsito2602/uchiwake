# 個人・共有スペース

アカウントごとに本人専用の個人スペースを1つ持ち、共有スペースは複数作成・参加できます。
右上のボタンは、追加ボタンと同じ背景ブラーと奥行きの動きを使います。
一覧には閉じるボタンを置かず、背景タップで追加メニューと同じ速度・イージングの逆再生で閉じます。文字の太さも追加メニューに揃えます。
作成・参加・設定・招待・負担設定には既存のフローティングパネルを使い、スマートフォンでは戻る・保存・参加・共有などをボトムナビに配置します。
選択月・タブを維持して切り替え、最後の選択をアカウント別に端末へ保存します。
編集中・取り込み中は切り替えを閉じ、入力内容の別スペースへの保存を防ぎます。

## 設定画面

設定トップには「スペース設定」の入口と、アプリ共通のアカウント・表示・デモ・更新設定を配置します。
「スペース設定」はフローティングパネルで開き、選択中のスペース名、スペース名・メンバー管理、カード、費目、負担、家賃を集約します。
右上の「このスペースの設定」も同じパネルを開きます。個人スペースでは負担・招待・メンバー削除を表示しません。
各項目の編集から戻ると、スペース設定のスクロール位置を保持して戻ります。保存・共有・戻るはスマートフォンのボトムナビ、PCではパネル下部に表示します。
子パネルを開いている間は親パネルを隠し、最前面だけがキー操作を受け取ります。背景のスクロールはすべて閉じたときに復帰します。
メンバーはGoogleのプロフィール画像を表示し、画像がない場合は名前の頭文字を使います。
カードの「使用する」、負担の「すべて同じ割合にする」、家賃の「家賃を使用する」は同じトグル部品とアニメーションを使います。

家賃の有効／無効はスペースごとに全メンバーへ反映します。初期状態は有効です。
無効時は精算画面と負担の費用別設定から家賃を隠し、全期間の支出・精算・履歴グラフから基本家賃と月別家賃を除外します。
登録金額・適用月・月別上書き・負担割合は削除せず、再有効化すると同じ設定で集計します。デモの家賃は実設定と分離します。
保存時にリビジョンを検証し、別メンバーによる更新後の古い設定を409で拒否します。

追加表 `space_preferences` は `0011_space_preferences.sql` と同じ定義でAPIの初回利用時にも作成します。
既存の `0010` 適用済み環境にはGitHubへのpushだけで反映でき、後から `0011` を適用しても安全です。

## 共同編集と招待

- Google認証に加え、全家計APIで `X-Space-Id` と有効なメンバー登録を検証。
- 明細・カード・費目・固定費・負担設定はスペース内の全メンバーが編集可能。
- 招待、メンバー削除、スペース名変更、スペース削除は作成者のみ。個人スペースは招待・削除不可。
- 招待コードは12文字、48時間、1人用。DBにはSHA-256のみを保存。参加先と招待者を確認して参加。
- 招待文をコピー、またはOSの共有メニューからLINEへ送る。PWAの自動起動は必要としません。
- 10分あたり20回のコード試行制限。コード消費と参加登録をDBトランザクションで処理。
- メンバー削除時には発行済み招待を無効化。過去のメンバー名と割当額は保持。
- 15秒間隔とアプリ復帰時に再取得。編集中は自動再取得を止め、明細・負担設定の古い版での保存は409で拒否。
- メール許可リスト `ALLOWED_EMAILS` は維持しています。ステージングに招待する相手は、先にログイン許可済みのアカウントにしてください。一般公開時の登録受付は別途対応が必要です。

## 精算

個人は支出合計、共有は本人の負担額を表示。全員の割当額は「負担の内訳」からフローティングパネルで確認します。
内訳は本人を先頭にアイコン・名前・金額を並べ、人数が多い場合はパネル内だけでスクロールします。
対象者を選び、均等または0.01%単位の割合指定ができます。割合は合計100%。
「すべて同じ割合にする」をオフにすると、カードごと・家賃・そのほかの固定費ごとに設定できます。
オンに戻しても個別の設定は保持。明細1件ごとの割当は未実装です。

端数は最大剰余法で配分し、同率時はユーザーID順で固定。返金も合計に一致します。
端数調整がある場合は内訳の入口に「端数調整あり」、対象者の金額の下に「端数調整 +1円を含む」などを表示します。費用別設定は調整額を合算し、返金のマイナス調整も示します。
基本設定は適用開始月を持ち、月のデータ表示時に設定を保存します。
保存済みの月は、基本設定やメンバー追加によって変更されません。
「この月だけ」で明示的に編集できます。新規スペースは作成者が100%を負担する初期設定です。
招待したメンバーは自動で精算対象にならないため、参加後に負担設定で選択してください。

## データ移行・反映手順

このブランチは `0010_spaces.sql` が必要です。旧アプリと同時運用せず、DB移行と新コードのデプロイを続けて実施してください。

1. D1のバックアップ／復元ポイントを確認する。
2. `ALLOWED_EMAILS` の先頭が既存家計を管理する本人のメールであることを確認する。
3. `npm run check` を実行する。
4. 対象のD1に `npm run db:staging` で移行する。
5. このブランチのコードをステージングへデプロイする。
6. 本人がログインして既存の「うちの家計」を引き継ぎ、相手を招待し、負担設定を保存する。

既存レコードはすべて `legacy` 共有スペースに保持し、新しい個人スペースは空で作成します。
既存共有スペースを初めて所有できるのは `ALLOWED_EMAILS` 先頭のアカウントだけです。
ほかの許可済みアカウントには、改めて招待コードで参加してもらいます。
従来の固定2人折半にはGoogleアカウントとの対応がなかったため、自動で相手へ割り当てません。
既存月についても、必要な対象者・割合を確認して保存してください。

明細と金額を保持したまま、家賃・費目のキーをスペースとの複合キーに変更します。
カード削除は論理削除にし、過去のカード別割合の対応を保持します。
スペース削除も論理削除で、そのスペースへの全メンバーのアクセスを止めます。

## 検証

`tests/spaces.test.mjs` はSQLiteで実マイグレーションを実行し、個人・共有の分離、所有者移行、招待の期限・使用制限・同時使用、3人参加、権限、月別設定、履歴、明細編集の競合、メンバー削除後の遮断を確認します。
既存のカード・費目・AI取り込みテストもスペース指定に対応しています。
