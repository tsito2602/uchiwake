# iPhoneホーム画面アイコン

## 現在のSVGアイコンの作り方

### v7の実機結果と現在の調査

2026-09-28 14:10のユーザー画像で、Kondoはライトで白背景、うちわけv7は黒背景のままと確認。
v7の太い白縁は反映されており、前回の全候補透過・manifest固定では解決しなかった。
以後、透過化や新URLだけで解決したと説明しない。

`/__icon-check/light-v7/` に同じ登録条件の比較を用意。stagingでのみ配信する。
A=配信中のKondo画像そのもの、B=現行うちわけPNGそのもの、C=濃い部分だけ純黒、D=図柄全体が純黒。
まずA/Bを追加し、Aだけ白ならC/Dを比較する。全案で白縁・透明度は維持する。
原画のプレビューで白背景に見えることは、iOSの背景自動合成の成功を意味しない。
配色だけで直る根拠はまだなく、通常アプリの採用アイコンはv7のまま維持する。
固定データの取得元・ハッシュは `scripts/fixtures/README.md`。

2026-09-28、ユーザーが「Kondoのようにアイコンのみ白い縁取り」「アプリ内はライト／ダークを使い分け」と指定。
白いフチをなくす方針を置き換え、ホーム画面用だけに意図的な白い細縁を付ける。
輪郭補間を比較する未公開の試作は取り下げ、通常アプリには追加しない。

### 現行v7：白縁を仕切りと同じ太さにする

ユーザーの「区画間の太さに全体的なフチの太さを合わせて」に対応。
仕切りは原稿上で約25単位なので、背面の `stroke-width` を50にする。
色付きパスが線の内側半分を覆い、見える外周・内周・1画目の白縁が25単位になる。
180px表示では約 `25 × 1.14 × 180 / 1254 = 4.09px`。
仕切りの形と幅、透過、14%拡大、アプリ内のロゴは維持する。
白縁同士が接触しないよう、ホーム画面用の1画目だけ原稿上で28単位上へ移動する。
登録先は `/apple-touch-icon-v7.png` と `/icon-v7-{192,512}.png`。

同時に「ライトでも背景が黒い」「同じ端末でKondoは白くなる」と実機報告があった。
v6にはPNG以外に背景付きSVGのmaskable候補とテーマ別manifestの差し替えが残っていた。
v7は全ホーム画面候補（SVG・PNG・旧テーマ別URL）を背景なしの同じ図柄に揃える。
`src/boot.ts` はfavicon・manifestをテーマで差し替えず、アプリ内のロゴと色だけ更新する。
manifestの背景色・テーマ色はKondo同様の白で固定するが、画像には白背景を描かない。
これは確認できた実装差分の修正であり、iOSがどの画像を選びどう加工したかの断定ではない。
過去のv4でも共通透過画像では直らなかった報告があるため、今回は太い白縁を含むv7として実機確認が必要。
Appleの[Web Clip指定](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html)はPNGの明示指定を案内しているが、ライト／ダーク背景の自動合成条件は説明していない。

### v6：連続した円グラフの白縁と仕切り

ユーザーのv5実機画像で白縁の表示を確認。さらに「もう少し太く」「円グラフを囲み、白線で仕切る」と指定された。
v6は白縁の線幅を18から24へ増やし、180px表示で片側約1.96pxにする。
円グラフ4区画は `chartOutline` という一つの白い輪郭でつなぐ。
元の外周・内周の曲線をたどり、3か所の区画間だけを橋渡しする。
その上に元の色付きパスを重ねることで、暗い隙間や二重線のない白い仕切りになる。
1画目は別の白縁を保ち、中央の穴と1画目との間は透明のまま。
登録先は `/apple-touch-icon-v6.png` と `/icon-v6-{192,512}.png`。
PNGの透過・書き出し条件・14%拡大・アプリ内の明暗切替はv5から維持する。

### 実機で白縁が見えなかった報告への修正（v5）

白縁追加後もユーザーのホーム画面では縁が見えなかった。一方、配信中の
`/icon-dark.svg` には白縁レイヤーが存在することを確認した。
旧アイコンの保持かiOS側の候補選択・加工かは、この画像だけでは確定できない。
Kondoには明示的な `apple-touch-icon` PNG指定があり、うちわけにはなかったため、
ホーム画面用をKondoのPNG書き出し・指定方法に揃える。

- `apple-touch-icon` は新しいURL `/apple-touch-icon-v5.png`（180px）を指定。
- Kondoの `scripts/render-touch-icon.mjs` と同じ `density:384`、`compressionLevel:9`、`palette:false`。
- 図柄と白縁だけをRGBA PNGへ焼き込み、背景矩形は含めない。`removeAlpha()` や白背景合成はしない。
- manifestの通常アイコンも同じ原稿の192px・512px PNG。明暗で同じ画像を使う。
- SVG faviconとmaskable候補のテーマ別背景は維持する。PNGに流用しない。
- Kondoの片側約1.4pxに合わせ、うちわけは180pxで片側約1.47pxの白線にする。
- アプリ内の縁なしロゴ・テーマ切替・起動アニメーションは変更しない。

過去の縁なしPNGでライト背景が黒くなった実機報告は未解決の経緯として保持する。
v5はユーザー画像で暗い背景上の白縁を確認済み。ライトでの背景加工とv6の実機表示は未確認。既存アイコンの自動更新も保証しない。
確認はSafariで更新後のページからホーム画面へ追加して行い、元のアイコンを先に削除する必要はない。

### ホーム画面用

1. `src/brand-motion.ts` の `pathData` 5本を原本に使う。形は変更しない。
2. `scripts/build-brand.mjs` で `viewBox="0 0 1254 1254"` のSVGを生成する。
3. SVG・PNGとも背景矩形を含めない。faviconやmaskableを含め、黒い背景付き候補を残さない。
4. 図柄全体を `translate(627 627) scale(1.14) translate(-627 -627)` で14%拡大する。
5. Kondoのように図柄の背面へ白縁専用のグループを置く。
   `data-appearance="edge"`、`fill="#FFFFFF"`、`stroke="#FFFFFF"`、`stroke-width="50"`、
   `stroke-linejoin="round"` として、1画目と円グラフの連続輪郭 `chartOutline` の2本を描く。
6. その上に通常の5本のパスを描く。白線の内側半分は図柄で覆われ、外側だけ細い縁として見える。
   180px表示で片側約 `25 × 1.14 × 180 / 1254 = 4.09px`。区画間の仕切りと同程度の太さ。
7. ホーム画面の図柄は明暗ともライト配色を使う。`ink=#30302f`、`mid=#9c978f`、`pale=#cbc5bb`。
   PNG・SVGとも背景は透明で、ホーム画面候補はテーマで差し替えない。

白縁は意図した図柄の一部であり、除去対象のにじみではない。
中央の穴と1画目との間は透明。円グラフの区画間は白い仕切りで埋める。背景面は追加しない。
faviconは `/icon.svg`。旧 `/icon-light.svg`・`/icon-dark.svg` も同じ透過データで維持する。
Apple Touch Iconは上記v7 PNG。manifest ID `/` と家計データも維持する。

### アプリ内

- `public/logo-light.svg` / `public/logo-dark.svg` は従来の縁なしデータを保持する。
- ライトは暗い図柄、ダークは明るい図柄。配色は `BRAND_THEMES` に従う。
- 起動画面は `src/boot.ts` / `drawBrand`、ログイン画面は `src/auth.tsx` / `src/login.css` で切り替える。
- 白縁レイヤーとホーム画面用の14%拡大をアプリ内へ流用しない。

### 再生成と検証

```sh
node scripts/build-brand.mjs
npm run check
```

`npm run dev` / `npm run build` でも生成される。生成SVGを直接手直ししない。
テストでは白縁の存在・中央の穴・SVG透過・ホーム画面の明暗共通の図柄・14%の大きさを確認する。
さらに登録先PNGの180pxでの白線・アルファ・再生成一致・WorkerのPNGバイト列とHTML指定を確認する。
アプリ内ロゴはハッシュで従来版との完全一致を確認する。iOS固有の追加ハイライトは別途実機で確認する。

## uchiwakeの経緯

- v2: 通常PNGは透過。maskableには不透明背景が残っていた。ユーザーから背景が透過しないとの報告。
- v3: maskableも透過にし、density 384で生成。ユーザーからライトでも背景が白くならないとの報告。
- v4: Kondoの再現手順6に合わせ、ホーム画面用の画像・favicon・manifestをテーマで差し替えない。
  アプリ内のロゴのみ明暗で切り替える。PNGは明暗共通の暗い図柄で、背景・隙間・中央の穴は透過。
  白い縁取りは追加しない。14%拡大した形状を維持する。

## v4の指定

- Apple Touch Iconとfavicon: `/brand-icons/apple-touch-v4.png`（180px、同じ画像）。
- manifest: `/manifest-v4.webmanifest`。192/512px・maskableも同じ原本と配色。
- manifestの `background_color` / `theme_color`: `#FFFFFF`（Kondoと同じ）。画像に白い面は描かない。
- PNG生成: SVGをdensity 384で読み込み、各サイズへ縮小。compressionLevel 9、palette false。
- インストールID `/` と保存データは変更しない。旧manifest URLも同じ参照画像へ揃える。

生成画像のアルファ・白い下地がないこと・テーマ切替時に参照が不変なこと・配信バイト列は自動検証する。
この検証ではiOSの背景自動合成までは確認できない。v4はユーザーから「変わらない」と報告された。
新しい版をSafariから追加して、ホーム画面のアイコン外観をライト／ダークで比較する。
新しいURLや再追加で必ず改善するとは説明しない。失敗した場合は成功したKondo比較Iと
同じページ・manifest条件で並べ、画像内容と登録条件の影響を分けて調べる。

## 2026-09-28 復元版を基準に背景除去・14%拡大

復元版にユーザーから「おっけーこの状態で」と了承があり、白い下地の除去と14%拡大を依頼された。
SVG内の背景矩形を削除し、図柄をキャンバス中央から1.14倍に拡大する。
SVGのURL・favicon・manifest・テーマ切替の方法は復元版のまま維持する。PNG化はしない。
アプリ内ロゴと起動アニメーションは変更しない。輪郭や白い下地は追加せず、隙間は透過する。
この背景除去版は、後のユーザー実機確認でライトでも黒い背景になると報告された。

## 2026-09-28 背景除去版の失敗と最小差分への修正

ユーザーからライトで黒くなると再報告。「縮小前のまま、白い下地をなくすのと拡大するだけ」と指示。
基準版には白い縁取り専用のパスはなく、図柄5本と背景矩形だった。
基準版の背景矩形を残し、図柄5本だけを1.14倍にする構成へ修正する。
拡大グループを外すと基準版SVGとバイト単位で完全一致することをテストする。
図柄用の白い下地は追加しない。ホーム画面の背景色と図柄の下地を混同しない。
画像にないハイライトや縁がiOS側で付く可能性はあるが、この版の実機での結果は未確認。
